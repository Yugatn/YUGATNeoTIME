# Атлас времени: техническая спецификация v1.0

## Цель

Преобразовать идею главы 266 «Атлас времени: календарь календарей» в проверяемую архитектуру. Атлас не пытается объявить одну календарную систему универсально истинной и не смешивает исторические конвенции. Он хранит несколько представлений одного входного дня, включая происхождение и ограничения каждого результата.

## Каноническая запись слоя

Каждый объект слоя использует поля:

| Поле | Назначение |
|---|---|
| `id` | Стабильный машинный идентификатор |
| `system` | Название календаря или временной системы |
| `value` | Вычисленное представление |
| `method` | Правило или алгоритм преобразования |
| `source` | Источник правила, параметр или пользовательский ввод |
| `uncertainty` | Известные ограничения и неоднозначности |
| `status` | Эпистемический статус результата |

Корневой объект также сохраняет схему, исходную дату, опорный JDN и параметры расчёта. Значения и методы не должны терять свою связь при экспорте или визуализации.

## Конвейер

1. Получить дату вместе с явно названной календарной системой.
2. Проверить синтаксис и существование даты в исходном календаре.
3. Преобразовать её в опорный целочисленный JDN, если календарная система и историческая конвенция позволяют это сделать.
4. Запустить независимые адаптеры календарей.
5. Сформировать слой для каждого результата с методом, источником, неопределённостью и статусом.
6. Показать значения в интерфейсе и не скрывать ограничения.
7. Для неоднозначных исторических записей возвращать несколько кандидатов либо сообщать, что точное преобразование невозможно без контекста.

## Слои текущего MVP

- Григорианская дата — вход пользователя.
- JDN — вычисляемая опорная координата целочисленного дня.
- Юлианская дата — пролептическое преобразование того же JDN.
- Русское летоисчисление — предварительная модель сентябрьского стиля, помеченная `NOT_TESTED` с точки зрения исторической применимости.
- Maya Long Count, Tzolk'in и Haab' — вычисления относительно явно указанной корреляции.
- Древнеегипетский гражданский календарь — математическая 365-дневная последовательность от пользовательской эпохи, не универсальный исторический конвертер.

## Принципы корректности

- Не считать совпадение фаз календарей доказательством причинной связи.
- Не подменять неизвестную эпоху догадкой.
- Не применять единый сдвиг ко всем историческим русским датировкам.
- Сохранять исходную запись и выбранную конвенцию.
- Отделять вычислительную корректность от исторической применимости.
- Для каждой конвертации указывать, что именно известно, вычислено, заявлено или пока не проверено.
