# YUGATNeoTIME — Синтез времени

**Цель:** исследовательский проект для сопоставления разных календарных систем и представления времени как нескольких согласованных слоёв, а не одной универсальной шкалы.

## MVP

Откройте [веб-приложение](./index.html) локально в браузере или опубликуйте репозиторий через GitHub Pages (**Settings → Pages → Deploy from a branch → main → / (root)**).

В первой версии реализованы:
- григорианская дата как гражданская точка отсчёта;
- календарь Майя: Long Count, Tzolk'in и Haab';
- настраиваемая корреляционная константа GMT (по умолчанию 584283);
- явное отображение выбранной константы и предупреждение, что корреляция — историко-исследовательский параметр;
- обратное преобразование: ввод номера дня Long Count и получение григорианской даты;
- разделение вычисляемых значений, принятых соглашений и ещё не моделируемых календарей.

## Запуск

Приложение не требует сборки, зависимостей или сервера. Откройте **index.html** в современном браузере. Все вычисления выполняются локально.

## Метод и ограничения

- Внутреннее представление использует целочисленный номер юлианского дня (JDN) для григорианской даты.
- Long Count рассчитывается как **JDN − GMT correlation**.
- Tzolk'in и Haab' рассчитываются по циклическим индексам относительно принятой эпохи Long Count **0.0.0.0.0 = 4 Ajaw 8 Kumk'u**.
- Корреляция GMT 584283 — распространённый выбор, а не бесспорное доказательство единственной исторической привязки. Значение можно изменить в интерфейсе.
- Это прототип синтеза календарей, а не утверждение, что календарные циклы управляют событиями или человеческим поведением.
- В текущем MVP ещё нет полноценной поддержки исторических русских календарных дат, юлианского календаря как независимого режима, часовых поясов, времени суток и неопределённости исторических источников.

## План развития

1. Ввести единый формат даты с календарной системой, эпохой, точностью и источником.
2. Добавить юлианский календарь и исторические русские датировки до реформы Петра I с явными правилами преобразования.
3. Добавить циклические, астрономические и персональные слои времени.
4. Создать набор эталонных тестов и проверять конвертацию на границах циклов.
5. Отделить вычислительное ядро от интерфейса и хранить выбранные соглашения в экспортируемом профиле.

## Эпистемические метки

- **OBSERVED** — проверяемый ввод или результат вычисления.
- **DERIVED** — значение, полученное по явно заданному алгоритму.
- **CLAIMED** — историческое или интерпретационное утверждение, требующее источника.
- **NOT_TESTED** — ещё не проверенная гипотеза или функция.
- **RESIDUAL** — неизвестные и ограничения, которые модель пока не описывает.

Проект исследовательский. Исторические даты и корреляции следует сопровождать источниками, а спорные соответствия не скрывать за точным видом результата.
